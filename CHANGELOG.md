## [1.0.6] - 2026-09-22

### Added

- **Приоритетная страна (`PREFERRED_COUNTRY`).**
  - Новый параметр в `observer_config.py`.
  - Если задан код страны (например, `'DE'`) — observer в первую очередь берёт ссылки с этой страной:
    - при поиске основной ссылки при старте;
    - при пополнении резерва из файла.
  - Если пустая строка (`''`) — приоритета нет, все страны равны.
  - Если код невалидный — игнорируется с предупреждением в лог.
  - **Приоритет — это не ограничение.** Если ссылок с этой страной нет или они мертвы, observer добирает из остальных стран.
  - В логе при старте:
    ```
    ⭐ Приоритетная страна: DE
    ```
    или
    ```
    Приоритетная страна: не задана
    ```

- **Система триггеров через файлы в `/tmp/`** (`triggers.py`).
  - Позволяет управлять observer'ом через **файлы-триггеры** — из Telegram-бота или вручную.
  - **Проверка свежести:** если триггер старше `TRIGGER_MAX_AGE` (по умолчанию 30 сек) — удаляется **без выполнения**. Защита от выполнения устаревших команд после падения/перезапуска observer'а.
  - **Чистка при старте:** все старые триггеры и ответы удаляются при запуске observer'а.
  - **Ответы** пишутся в `/tmp/vless_<action>_response` в формате **JSON**.

- **Триггеры для управления observer'ом:**

  | Файл | Действие |
  |------|----------|
  | `/tmp/vless_status_trigger` | Запрос статуса (primary, резерв, deferred, переключения) |
  | `/tmp/vless_links_trigger` | Список всех ссылок (primary, backup, deferred, dead, карантин) |
  | `/tmp/vless_switch_trigger` | Принудительное переключение на следующую живую из резерва |
  | `/tmp/vless_geo_DE` | Переключиться на первую живую ссылку страны DE |
  | `/tmp/vless_pick_46.28.69.53` | Переключиться на конкретный host |
  | `/tmp/vless_ignore_46.28.69.53` | Отправить ссылку в карантин |
  | `/tmp/vless_unignore_46.28.69.53` | Убрать ссылку из карантина |
  | `/tmp/vless_reload_trigger` | Перечитать `working_links.txt` |

- **Новый модуль `vless_common.py`.**
  - Общие функции, которые используются и в `observer.py`, и в `triggers.py`.
  - Вынесены для **устранения циклических импортов**.
  - Содержит: парсинг ссылок, работу с гео, Xray-проверку, обновление 3x-ui, атомарное чтение файлов.
  - Никаких обратных зависимостей от observer'а — все функции **самодостаточны**.

- **Новый модуль `triggers.py`.**
  - Логика всех триггеров.
  - Функция `check_and_handle(observer)` — вызывается из `test_primary`.
  - Функция `cleanup_triggers_on_startup()` — вызывается при старте observer'а.

- **Новые параметры в `observer_config.py`:**
  ```python
  # Приоритетная страна
  PREFERRED_COUNTRY = ""

  # Максимальный возраст триггера (сек)
  TRIGGER_MAX_AGE = 30
  ```

- **Совместимость со старыми триггерами.**
  - `/tmp/vless_observer_trigger` — работает как раньше.
  - `/tmp/vless_quarantine_trigger` — работает как раньше.
  - `/tmp/vless_deep_check_trigger` — работает как раньше.

### Changed

- **`observer.py` разделён на модули.**
  - `vless_common.py` — общие функции.
  - `triggers.py` — триггеры.
  - `observer.py` — только логика observer'а.
  - Все общие функции теперь импортируются из `vless_common`.
  - Логирование из `vless_common` и `triggers` идёт в тот же лог, что и observer.

- **`test_primary` сначала проверяет триггеры.**
  - Порядок проверки:
    1. Триггеры от бота (`check_and_handle`).
    2. Старые триггеры (`vless_observer_trigger` и т.д.).
    3. Обычная проверка основной ссылки.

- **`install.sh` обновлён.**
  - Добавлена установка `vless_common.py` и `triggers.py`.
  - Проверки импорта новых модулей.
  - В итоге выводится список доступных триггеров для бота.

- **`update.sh` обновлён.**
  - `vless_common.py` и `triggers.py` обновляются как код.

### Fixed

- Не выявлено.

## [1.0.5] - 2026-09-17

### Added

- **Показ `fail_count` в логе статуса observer'а.**
  - Строка статуса показывает, сколько отказов подряд у текущей основной:
    ```
    OK | 31.76.109.18 [NL] | отказов: 3/5 | резерв: 4/4 живых | отложено: 6 | перекл: 2
    ```
  - Показывается **только если** `fail_count > 0`.

- **Защита от «круговорота» основной ссылки (`recently_primary`).**
  - После переключения старая основная **исключается из кандидатов** на `RECENTLY_PRIMARY_COOLDOWN` секунд (по умолчанию 60).
  - Потом она **может вернуться** в резерв.

- **Новый параметр в `observer_config.py`:**
  ```python
  RECENTLY_PRIMARY_COOLDOWN = 60
  ```

### Changed

- **В логе при переключении** появляется запись:
  ```
  ⏸️ team.betust.net [NL] в recently_primary на 60с
  ```

## [1.0.4] - 2026-09-17

### Fixed

- **Observer проверяет резервные ссылки перед добавлением в пул.**
  - Раньше: когда резервная ссылка умирала, observer брал следующую из файла **без проверки**.

- **`switch_to_backup` использует проверку кандидатов.**

- **`update_pool_from_file` больше не добавляет ссылки в пул без проверки.**

### Changed

- **`refill_pool_excluding_deferred` заменён на `_fill_backup_pool_checked`.**

- **Логи стали информативнее.**

## [1.0.3] - 2026-09-14

### Added

- **Определение гео ссылок** (`vless_checker.py`).
  - Чекер при проверке рабочей ссылки **запрашивает её страну** через Cloudflare trace.
  - Результат записывается **в саму ссылку** — в fragment `#COUNTRY`.
  - Формат: `vless://uuid@host:443?params#DE`.
  - Если гео не определилось — `#UNKNOWN`, ссылка **не отбрасывается**.
  - Если ссылка **уже с `#remark`** — fragment **заменяется** на `#COUNTRY`.

- **Устойчивый импорт гео-параметров** через `getattr(cfg, ..., default)`.

- **Показ гео в логах observer'а.**
  - Формат: `OK | 188.130.208.210 [DE] | резерв: 4/4 живых | ...`
  - Если `#` нет или fragment не распознан — `[N/A]`.
  - Если `#UNKNOWN` — `[UNKNOWN]`.

- **Гео-распределение в логе чекера.**

- **Новые параметры в `vless_check_config.py`:**
  ```python
  GEO_ENABLED = True
  GEO_URL = "https://www.cloudflare.com/cdn-cgi/trace"
  GEO_TIMEOUT = 5
  GEO_UNKNOWN_MARK = "UNKNOWN"
  ```

### Changed

- **`vless_checker.py`: fragment отсекается перед парсингом.**

- **`observer.py`: сравнение ссылок — без гео.**

## [1.0.2] - 2026-09-14

### Added

- **Умное слияние конфигов при обновлении** (`merge_config.py`).
  - Дополняет пользовательские конфиги новыми параметрами из GitHub.
  - Существующие параметры **не трогаются**.
  - Показывает, **что** будет добавлено, и спрашивает подтверждение.
  - При отказе — конфиг остаётся **без изменений**.
  - В режиме `--auto` — слияние **пропускается**.

- **`update.sh` обновляет конфиги через `merge_config.py`.**

- **`install.sh` скачивает `merge_config.py`.**

### Changed

- **`update.sh` разделяет обновление кода и конфигов.**

## [1.0.1] - 2026-09-14

### Fixed

- **Observer проверяет ссылки при старте.**
  - Раньше: сразу ставил первую ссылку из `working_links.txt` в outbound 3x-ui, **не проверяя** её.

- **`init_pool` возвращает `bool`.**

- **`run()` — цикл с ожиданием.**

### Changed
