## [1.0.0] - 2026-09-14

Первый публичный релиз. **Alpha 1.0.**

### Added

- **Этап 1: сбор VLESS-ссылок** (`vless_checker.py`).
  - Скачивание списка с GitHub.
  - Фильтрация по `security=reality` и порту `443`.
  - Проверка каждой ссылки через реальный Xray (HTTPS-запрос на `check.torproject.org`).
  - Отбор ТОП-30 по пингу в `working_links.txt`.

- **Observer: трёхпоточный наблюдатель** (`observer.py`).
  - Поток 1 — проверка основной ссылки каждые 5 сек.
  - Поток 2 — проверка резерва каждые 30 сек.
  - Поток 3 — deferred-ссылки (раз в 10 минут) + обновление пула.
  - Разные порты для потоков: 10808 / 10809 / 10810.
  - Автоматическое переключение outbound'а в 3x-ui через SQLite.
  - Механика отложенных ссылок (deferred) с двумя таймерами: перепроверка раз в 10 минут, удаление через 2 часа.
  - Карантин для ссылок, работающих только на Google.
  - Автоматическая чистка `working_links.txt` от мёртвых.

- **Ротация логов.**
  - Каждый лог ротируется в полночь.
  - Хранится 7 архивов.

- **Graceful shutdown.**
  - SIGTERM/SIGINT handler во всех трёх скриптах.
  - Корректное завершение: закрытие сокетов, убийство дочерних Xray-процессов.

- **Триггеры для отладки** (файлы в `/tmp/`):
  - `vless_observer_trigger` — имитация отказа.
  - `vless_quarantine_trigger` — отправить основную в карантин.
  - `vless_deep_check_trigger` — глубокая проверка (Google + запрещённые).

- **`show_logs.sh` — меню логов и управления.**
  - Просмотр логов Observer, Чекера, cron-обёртки.
  - Статистика переключений.
  - Очистка логов.
  - Триггеры.
  - Статус служб и активных процессов.
  - Просмотр ротированных архивов.

- **`install.sh` — установщик.**
  - Проверка системы и прав.
  - Установка зависимостей (Python, pip, sqlite3, jq).
  - Скачивание файлов чекера и observer'а с GitHub.
  - Настройка cron (01:00, 07:00, 13:00, 19:00).
  - Создание и запуск systemd-службы `vless_observer`.
  - Прогресс-бар установки.
  - Проверки: конфиги, модули, Xray.

- **Защита от двойного запуска чекера.**
  - `flock` в cron-задании.
  - Если предыдущий прогон ещё работает — новый не запустится.

- **Автообновление через `update.sh`.**
  - Проверка версии на GitHub.
  - Бэкап перед обновлением (5 последних).
  - Graceful stop/start observer'а.
  - Откат из последнего бэкапа (`--rollback`).
  - Флаги: `--check`, `--auto`, `--rollback`.

### Changed

- **Observer читает `working_links.txt`** (30 ссылок), а не `stable_links.txt` (10).
  - Этап 2 (`server_tester.py`) по-прежнему работает, но его результат observer'ом **не используется**.
  - Оставлен как резервный / для отдельного анализа.

- **Отложенные ссылки перепроверяются раз в 10 минут.**
  - Было: каждую минуту (баг — счётчик не сбрасывался после проверки).
  - Стало: два поля `deferred_at` и `last_checked_at`.
  - Нагрузка на CPU от deferred-потока снижена в ~10 раз.

- **Валидация Reality-параметров** (`pbk`, `sid`, `sni`).
  - Пустой `publicKey` — ссылка отбрасывается.
  - Подозрительно длинный `shortId` (>16 символов) — отбрасывается.
  - Пустой `serverName` — отбрасывается.

- **Обновление `working_links.txt` через атомарную запись.**
  - `tmp + os.replace` — observer никогда не прочитает недописанный файл.

- **`reload_xray` больше не использует SIGHUP.**
  - Xray не поддерживает SIGHUP для перезагрузки конфига.
  - Теперь — честный `systemctl restart x-ui` с таймаутом.

- **`switch_to_backup` — цикл вместо рекурсии.**
  - Раньше: рекурсивный вызов при неудаче переключения.
  - Теперь: `for attempt in range(max_attempts)`.

### Fixed

- **`start_time` в начале `test_link_through_xray`.**
  - Раньше: мог быть `NameError` в `except`, если ошибка до инициализации.
  - Теперь: `start_time = time.time()` — первая строка функции.

- **Сокеты Xray корректно закрываются в `finally`.**
  - Даже при исключении — `s.close()` вызывается.
  - `_kill_process` с ожиданием завершения (fix утечки zombie-процессов).

- **`self.primary is None` в финальном логе.**
  - Раньше: `AttributeError` при завершении, если `init_pool` упал.
  - Теперь: проверка `if self.primary` перед `parse_vless_link`.

- **Защита от гонок в `backup_pool`, `dead_links`, `deferred_links`.**
  - Отдельные `threading.Lock` для каждой структуры.

- **Реальная остановка `until_30` в `vless_checker.py`.**
  - Раньше: при `CHECK_MODE = 'until_30'` все фьючерсы создавались сразу, «остановка» была фиктивной.
  - Теперь: работа чанками (`max_workers * 4`), при достижении цели новые задачи не submit-ятся.

- **`STAGE2_MIN_RESPONSE_SIZE` теперь используется.**
  - Раньше: параметр объявлен, но не проверялся в `is_stable`.
  - Теперь: учитывается `avg_response_size >= STAGE2_MIN_RESPONSE_SIZE`.

- **`systemd` юнит `vless_observer` корректно завершает службу.**
  - Убраны `ExecReload`, `PIDFile`, `StandardOutput=append:`.
  - Добавлены `KillSignal=SIGTERM`, `TimeoutStopSec=30`, `StandardOutput=null`, `StandardError=journal`.

### Removed

- **`full_check.py`** — не использовался, заменён на `run_full_check.sh`.

## Как выпускать новые версии

1. **Внести изменения** в код.
2. **Добавить запись** в раздел `[Unreleased]` этого файла.
3. **При релизе:**
   - Переименовать `[Unreleased]` → `[X.Y.Z] - YYYY-MM-DD`.
   - Добавить новый пустой `[Unreleased]` сверху.
   - Обновить `VERSION` на `X.Y.Z`.
   - Закоммитить и запушить.
4. **На серверах:**
   - `bash /root/update.sh` — подтянет новую версию.

**Правила версионирования:**

| Изменение | Версия |
|-----------|--------|
| Только багфиксы | `1.0.0` → `1.0.1` |
| Новая функция (обратно совместимая) | `1.0.0` → `1.1.0` |
| Ломающие изменения | `1.0.0` → `2.0.0` |
