## [1.0.12] - 2026-10-08

### Fixed

- **Чистка порта от мусора в `parse_vless_params` (`vless_checker.py`).**
  - **Проблема:** источник иногда генерирует ссылки вида `host:443/?params`, с `/` после порта.
  - **Раньше:** `int('443/')` → `ValueError` → `EXCEPTION`. Ссылка **отбрасывалась** (даже если рабочая).
  - **Теперь:** порт чистится регуляркой `^(\d+)` → `443`. Ссылка проходит.
  - Итог: **сколько-то «потерянных» ссылок** в 1.0.11 → **0** в 1.0.12.

- **`checked_count` инкрементится при EXCEPTION.**
  - **Проблема:** при `EXCEPTION` счётчик не рос. В логе — «проверено 1453/2223» вместо 2223.
  - **Теперь:** `checked_count += 1` при любом исходе (OK / FAIL / TIMEOUT / EXCEPTION).

- **Валидация порта в `filter_links`.**
  - Отсеивает порт ≤ 0 или > 65535 как `bad_port`.
  - В логе — счётчик `битый порт: N`.

### Changed

- **DEBUG-логи убраны** — уровень логирования обратно `INFO`.
- **Лог финала расширен:** `checked=X/Y`, `TCP-отсеяно: N`, `битый порт: N`.

### Note

- **Функциональность 1.0.11 сохранена** (TCP-предпроверка, shuffle).

## [1.0.11] - 2026-10-07

### Added

- **TCP-предпроверка перед Xray-проверкой** (`vless_checker.py`).
  - Перед запуском Xray на каждой ссылке — быстрый TCP-connect к серверу.
  - Если latency > `TCP_PRECHECK_MAX_LATENCY_MS` (2000 мс) или connect не удался — Xray **не запускается**.
  - Цель: экономия CPU и времени на заведомо мёртвых серверах.
  - Ожидаемая экономия: **30–50% времени** этапа 1.
  - Новые параметры: `TCP_PRECHECK_ENABLED`, `TCP_PRECHECK_TIMEOUT`, `TCP_PRECHECK_MAX_LATENCY_MS`.

- **Перемешивание списка перед проверкой** (`vless_checker.py`).
  - Перед началом проверки чанками — список **перемешивается один раз**.
  - Чекер не идёт по списку сверху вниз, а берёт случайные ссылки.
  - Не ломает логику чанков.
  - Новый параметр: `SHUFFLE_BEFORE_CHECK`.

- **Счётчик TCP-отсеянных** в логе финала: `(TCP-отсеяно: N)`.

## [1.0.10] - 2026-10-07

### Fixed

- **Observer сбрасывает `dead_links` при обновлении файла ссылок** (`observer.py`).
  - **Проблема:** если ссылка была помечена мёртвой (в `dead_links`), а чекер через 6 часов её снова нашёл и сохранил в `working_links.txt` — observer её **игнорировал** до рестарта.
  - **Причина:** `dead_links` — в памяти, не синхронизирован с файлом.
  - **Решение:** при **изменении** `working_links.txt` (сравнение через `set`) — `dead_links` **сбрасывается**.
  - Теперь ожившая ссылка, сохранённая чекером — **снова доступна** observer'у без рестарта.

### Changed

- **`update_pool_from_file`** — сравнивает старый и новый списки через `set`, при изменении сбрасывает `dead_links`.

## [1.0.7] - 2026-09-22

### Added

- **Двойная проверка резервных ссылок** (`observer.py`).
  - Новая функция `test_link_double_check` в `vless_common.py`.
  - Перед добавлением в резерв ссылка проверяется **N раз с интервалом**.
  - В резерв попадают только те, которые **ВСЕ N проверок** прошли успешно.
  - Отсеивает ссылки, которые отвечают **1 раз из N** — нестабильные.
  - Работает **и при старте**, **и во время работы**.

- **Проверка перед переключением.**
  - В `switch_to_backup` — перед тем как поставить ссылку как основную, observer **проверяет её прямо сейчас**.
  - Если ссылка **мертва** — в deferred, берётся **следующий** кандидат из пула.

- **Новые параметры в `observer_config.py`:**
  ```python
  BACKUP_CHECK_ATTEMPTS = 2
  BACKUP_CHECK_INTERVAL = 2
  ```

### Changed

- **Логи стали информативнее.**
  - При пополнении резерва показывается, сколько проверок делается.
  - При переключении — проверка перед переключением.

### Fixed

- **Проблема «резервные вроде есть, но при переключении связь сразу падает».**
  - Раньше: одна успешная проверка давала ложное «жива».
  - Теперь: ссылка проходит **двойную проверку** при добавлении в резерв и **проверку перед переключением**.

## [1.0.6] - 2026-09-22

### Added

- **Приоритетная страна (`PREFERRED_COUNTRY`)** (`observer_config.py`).
  - Если задан код страны (например, `'DE'`) — observer в первую очередь берёт ссылки с этой страной:
    - при поиске основной ссылки при старте;
    - при пополнении резерва из файла.
  - Если пустая строка (`''`) — приоритета нет, все страны равны.
  - Если код невалидный — игнорируется с предупреждением в лог.
  - **Приоритет — это не ограничение.** Если ссылок с этой страной нет или они мертвы, observer добирает из остальных стран.

- **Система триггеров через файлы в `/tmp/`** (`triggers.py`).
  - Управление observer'ом из Telegram-бота или вручную.
  - **Проверка свежести:** если триггер старше `TRIGGER_MAX_AGE` (по умолчанию 30 сек) — удаляется **без выполнения**.
  - **Чистка при старте:** все старые триггеры и ответы удаляются при запуске observer'а.
  - **Ответы** пишутся в `/tmp/vless_<action>_response` в формате **JSON**.

- **Триггеры для управления observer'ом:**

  | Файл | Действие |
  |------|----------|
  | `/tmp/vless_status_trigger` | Запрос статуса |
  | `/tmp/vless_links_trigger` | Список всех ссылок |
  | `/tmp/vless_switch_trigger` | Переключиться на следующую |
  | `/tmp/vless_geo_DE` | Переключиться на страну DE |
  | `/tmp/vless_pick_46.28.69.53` | Переключиться на host |
  | `/tmp/vless_ignore_46.28.69.53` | В карантин |
  | `/tmp/vless_unignore_46.28.69.53` | Из карантина |
  | `/tmp/vless_reload_trigger` | Перечитать файл ссылок |

- **Новый модуль `vless_common.py`.**
  - Общие функции для `observer.py` и `triggers.py`.
  - Устранение циклических импортов.
  - Содержит: парсинг ссылок, работу с гео, Xray-проверку, обновление 3x-ui, атомарное чтение файлов.

- **Новый модуль `triggers.py`.**
  - Логика всех триггеров.
  - Функция `check_and_handle(observer)` — вызывается из `test_primary`.
  - Функция `cleanup_triggers_on_startup()` — вызывается при старте observer'а.

- **Новые параметры в `observer_config.py`:**
  ```python
  PREFERRED_COUNTRY = ""
  TRIGGER_MAX_AGE = 30
  ```

### Changed

- **`observer.py` разделён на модули.**
  - `vless_common.py` — общие функции.
  - `triggers.py` — триггеры.
  - `observer.py` — только логика observer'а.

- **`test_primary` сначала проверяет триггеры.**
  - Порядок проверки:
    1. Триггеры от бота (`check_and_handle`).
    2. Старые триггеры (`vless_observer_trigger` и т.д.).
    3. Обычная проверка основной ссылки.

- **`install.sh` обновлён.**
  - Добавлена установка `vless_common.py` и `triggers.py`.
  - Проверки импорта новых модулей.
  - В итоге выводится список доступных триггеров для бота.

- **`update.sh` обновлён.**
  - `vless_common.py` и `triggers.py` обновляются как код.

## [1.0.4] - 2026-09-17

### Fixed

- **Observer проверяет резервные ссылки перед добавлением в пул** (`observer.py`).
  - Раньше: когда резервная ссылка умирала, observer брал следующую из файла **без проверки** и ставил в пул как `alive: True`.
  - О том, что она тоже мертва, observer узнавал только через 30 секунд — в момент плановой проверки резерва.
  - И так **по одной каждые 30 секунд**, пока не находилась живая.
  - Теперь: observer **проверяет кандидата через Xray прямо в момент пополнения пула**.
  - Живая → в резерв. Мёртвая → в deferred, берём следующего кандидата.

- **`switch_to_backup` использует проверку кандидатов.**
  - Когда нет живых резервных — observer **проверяет кандидатов из файла** вместо того, чтобы брать первую попавшуюся.

- **`update_pool_from_file` больше не добавляет ссылки в пул без проверки.**
  - Перечитывает `self.links` из файла.
  - Пополнение резерва — только через проверку.

### Changed

- **`refill_pool_excluding_deferred` заменён на `_fill_backup_pool_checked`.**
  - Новая логика: поочерёдная проверка кандидатов.
  - Мёртвые сразу уходят в `deferred_links`.
  - Логи стали подробнее — видно каждого кандидата.

## [1.0.3] - 2026-09-14

### Added

- **Определение гео ссылок** (`vless_checker.py`).
  - Чекер при проверке рабочей ссылки **запрашивает её страну** через Cloudflare trace (`https://www.cloudflare.com/cdn-cgi/trace`).
  - Результат записывается **в саму ссылку** — в fragment `#COUNTRY`.
  - Формат: `vless://uuid@host:443?params#DE` (страна — код ISO 3166-1 alpha-2).
  - Если гео не определилось — `#UNKNOWN`, ссылка **не отбрасывается**.
  - Если ссылка **уже с `#remark`** — fragment **заменяется** на `#COUNTRY`.
  - Гео определяется **через тот же Xray-процесс**, что и основная проверка.

- **Устойчивый импорт гео-параметров** (`vless_checker.py`).
  - Параметры `GEO_*` читаются через `getattr(cfg, ..., default)`.
  - Если в конфиге нет `GEO_ENABLED` — берётся дефолт `True`.
  - Никаких `NameError` — код работает с любым конфигом.

- **Показ гео в логах observer'а** (`observer.py`).
  - Observer парсит `#COUNTRY` из ссылок и показывает её в логах.
  - Формат: `OK | 188.130.208.210 [DE] | резерв: 4/4 живых | ...`
  - Если `#` нет или fragment не распознан — `[N/A]`.
  - Если `#UNKNOWN` — `[UNKNOWN]`.

- **Гео-распределение в логе чекера** (`save_working_links`).
  - После сохранения ТОП-30 чекер пишет:
    ```
    Гео распределение: DE: 12, NL: 8, US: 5, UNKNOWN: 5
    ```

- **Новые параметры в `vless_check_config.py`:**
  ```python
  GEO_ENABLED = True
  GEO_URL = "https://www.cloudflare.com/cdn-cgi/trace"
  GEO_TIMEOUT = 5
  GEO_UNKNOWN_MARK = "UNKNOWN"
  ```

### Changed

- **`vless_checker.py`: fragment отсекается перед парсингом.**
  - При проверке ссылки через Xray — fragment (`#DE`) **не передаётся** Xray.
  - При сравнении с карантином — сравнение идёт **по базовой части** (без `#`).

- **`observer.py`: сравнение ссылок — без гео.**
  - Карантин, `backup_pool`, `deferred_links` — сравнение идёт по **базовой части** ссылки.

## [1.0.2] - 2026-09-14

### Added

- **Умное слияние конфигов при обновлении** (`merge_config.py`).
  - Новый скрипт `merge_config.py` — дополняет пользовательские конфиги новыми параметрами из GitHub.

- **`install.sh` скачивает `merge_config.py`.**
  - При установке — сохраняется в `/root/merge_config.py`.

### Changed

- **`update.sh` разделяет обновление кода и конфигов.**
  - **Код** (`.py` без конфигов, `.sh`) — перезаписывается.
  - **Конфиги** — обрабатываются через `merge_config.py`.

## [1.0.1] - 2026-09-14

### Fixed

- **Observer проверяет ссылки при старте** (`observer.py`).
  - Раньше: при запуске сразу ставил первую ссылку из `working_links.txt` в outbound 3x-ui, **не проверяя** её.
  - Если она оказывалась мёртвой — начиналось «дёргание»: 5 отказов → переключение → новая мёртвая → 5 отказов → снова переключение.
  - Теперь: observer **перебирает ссылки по одной** и ставит в outbound **только живую**.
  - Резерв наполняется **только живыми** ссылками. Мёртвые сразу уходят в deferred.
  - Если **все** ссылки в файле мёртвы — observer **не запускает потоки**, ждёт обновления файла от чекера.

- **`init_pool` теперь возвращает `bool`.**
  - `True` — нашли живую основную, работаем.
  - `False` — живых нет, надо ждать обновления от чекера.

- **`run()` — цикл с ожиданием.**
  - Observer не запускает рабочие потоки, пока не найдёт живую основную ссылку.
  - Файл `working_links.txt` перечитывается каждые 60 секунд, пока не появится живая ссылка.

### Changed

- **Старт observer теперь занимает больше времени.**
  - Хороший случай: 1–2 ссылки проверены → 5–10 секунд.
  - Плохой случай: 10+ мёртвых подряд → 40–90 секунд.
  - Очень плохой: все ссылки мёртвы → observer ждёт обновления файла от чекера.

## [1.0.0] - 2026-09-14

Первый публичный релиз. **Alpha 1.0.**

### Added

- **Этап 1: сбор VLESS-ссылок** (`vless_checker.py`).
  - Скачивание списка с GitHub.
  - Фильтрация по `security=reality` и порту `443`.
  - Проверка каждой ссылки через реальный Xray (HTTPS-запрос на `check.torproject.org`).
  - Отбор ТОП-30 по пингу в `working_links.txt`.

- **Observer: трёхпоточный наблюдатель** (`observer.py`).
  - Поток 1 — проверка основной ссылки каждые 5 сек.
  - Поток 2 — проверка резерва каждые 30 сек.
  - Поток 3 — deferred-ссылки (раз в 10 минут) + обновление пула.
  - Разные порты для потоков: 10808 / 10809 / 10810.
  - Автоматическое переключение outbound'а в 3x-ui через SQLite.
  - Механика отложенных ссылок (deferred) с двумя таймерами: перепроверка раз в 10 минут, удаление через 2 часа.
  - Карантин для ссылок, работающих только на Google.

- **Ротация логов.**
  - Каждый лог ротируется в полночь.
  - Хранится 7 архивов.

- **Graceful shutdown.**
  - SIGTERM/SIGINT handler во всех трёх скриптах.
  - Корректное завершение: закрытие сокетов, убийство дочерних Xray-процессов.

- **Триггеры для отладки** (файлы в `/tmp/`):
  - `vless_observer_trigger` — имитация отказа.
  - `vless_quarantine_trigger` — отправить основную в карантин.
  - `vless_deep_check_trigger` — глубокая проверка (Google + запрещённые).

- **`show_logs.sh` — меню логов и управления.**
  - Просмотр логов Observer, Чекера, cron-обёртки.
  - Статистика переключений.
  - Очистка логов.
  - Триггеры.
  - Статус служб и активных процессов.
  - Просмотр ротированных архивов.
  - Проверка обновлений, обновление, откат.
  - Просмотр и редактирование конфигов.

- **`install.sh` — установщик.**
  - Проверка системы и прав.
  - Установка зависимостей (Python, pip, sqlite3, jq).
  - Скачивание файлов чекера и observer'а с GitHub.
  - Настройка cron (01:00, 07:00, 13:00, 19:00) с защитой `flock`.
  - Создание и запуск systemd-службы `vless_observer`.
  - Прогресс-бар установки.
  - Проверки: конфиги, модули, Xray.
  - Скачивание `update.sh` и сохранение версии.

- **Защита от двойного запуска чекера.**
  - `flock` в cron-задании.
  - Если предыдущий прогон ещё работает — новый не запустится.

- **Автообновление через `update.sh`.**
  - Проверка версии на GitHub.
  - Бэкап перед обновлением (5 последних).
  - Graceful stop/start observer'а.
  - Откат из последнего бэкапа (`--rollback`).
  - Флаги: `--check`, `--auto`, `--rollback`.

### Changed

- **Observer читает `working_links.txt`** (30 ссылок), а не `stable_links.txt` (10).
  - Этап 2 (`server_tester.py`) по-прежнему работает, но его результат observer'ом **не используется**.
  - Оставлен как резервный / для отдельного анализа.

- **Отложенные ссылки перепроверяются раз в 10 минут.**
  - Было: каждую минуту (баг — счётчик не сбрасывался после проверки).
  - Стало: два поля `deferred_at` и `last_checked_at`.
  - Нагрузка на CPU от deferred-потока снижена в ~10 раз.

- **Валидация Reality-параметров** (`pbk`, `sid`, `sni`).
  - Пустой `publicKey` — ссылка отбрасывается.
  - Подозрительно длинный `shortId` (>16 символов) — отбрасывается.
  - Пустой `serverName` — отбрасывается.

- **Обновление `working_links.txt` через атомарную запись.**
  - `tmp + os.replace` — observer никогда не прочитает недописанный файл.

- **`reload_xray` больше не использует SIGHUP.**
  - Xray не поддерживает SIGHUP для перезагрузки конфига.
  - Теперь — честный `systemctl restart x-ui` с таймаутом.

- **`switch_to_backup` — цикл вместо рекурсии.**
  - Раньше: рекурсивный вызов при неудаче переключения.
  - Теперь: `for attempt in range(max_attempts)`.

### Fixed

- **`start_time` в начале `test_link_through_xray`.**
  - Раньше: мог быть `NameError` в `except`, если ошибка до инициализации.
  - Теперь: `start_time = time.time()` — первая строка функции.

- **Сокеты Xray корректно закрываются в `finally`.**
  - Даже при исключении — `s.close()` вызывается.
  - `_kill_process` с ожиданием завершения (fix утечки zombie-процессов).

- **`self.primary is None` в финальном логе.**
  - Раньше: `AttributeError` при завершении, если `init_pool` упал.
  - Теперь: проверка `if self.primary` перед `parse_vless_link`.

- **Защита от гонок в `backup_pool`, `dead_links`, `deferred_links`.**
  - Отдельные `threading.Lock` для каждой структуры.

- **Реальная остановка `until_30` в `vless_checker.py`.**
  - Раньше: при `CHECK_MODE = 'until_30'` все фьючерсы создавались сразу, «остановка» была фиктивной.
  - Теперь: работа чанками (`max_workers * 4`), при достижении цели новые задачи не submit-ятся.

- **`STAGE2_MIN_RESPONSE_SIZE` теперь используется.**
  - Раньше: параметр объявлен, но не проверялся в `is_stable`.
  - Теперь: учитывается `avg_response_size >= STAGE2_MIN_RESPONSE_SIZE`.

- **`systemd` юнит `vless_observer` корректно завершает службу.**
  - Убраны `ExecReload`, `PIDFile`, `StandardOutput=append:`.
  - Добавлены `KillSignal=SIGTERM`, `TimeoutStopSec=30`, `StandardOutput=null`, `StandardError=journal`.

### Removed

- **`full_check.py`** — не использовался, заменён на `run_full_check.sh`.
