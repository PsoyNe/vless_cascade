## [1.0.5] - 2026-09-17

### Added

- **Показ `fail_count` в логе статуса observer'а** (`log_status`).
  - Строка статуса теперь показывает, сколько отказов подряд у текущей основной:
    ```
    OK | 31.76.109.18 [NL] | отказов: 3/5 | резерв: 4/4 живых | отложено: 6 | перекл: 2
    ```
  - Показывается **только если** `fail_count > 0` — при нормальной работе строка не удлиняется.
  - Полезно видеть, что основная «шатается» — **до** того, как случится переключение.

- **Защита от «круговорота» основной ссылки** (`recently_primary`).
  - Раньше: после переключения старая основная **сразу возвращалась** в резерв — observer выкидывал её и тут же брал обратно.
  - Из-за этого в логах была «карусель»: одна и та же ссылка гуляла **основная → резерв → основная**.
  - Теперь: после переключения старая основная **исключается из кандидатов** на `RECENTLY_PRIMARY_COOLDOWN` секунд (по умолчанию 60).
  - Потом она **может вернуться** в резерв как обычная ссылка.
  - Полезно для реальных переключений и особенно — для **триггера** имитации отказа.

- **Новый параметр в `observer_config.py`:**
  ```python
  # Время (сек), в течение которого старая основная ссылка НЕ возвращается
  # в резерв после переключения.
  RECENTLY_PRIMARY_COOLDOWN = 60
  ```

### Changed

- **В логе observer'а при переключении** появляется запись:
  ```
  ⏸️ team.betust.net [NL] в recently_primary на 60с
  ```

- **`_get_candidates_from_file` фильтрует `recently_primary`.**
  - При пополнении резерва observer **не берёт** ссылки, которые недавно были основной.
  - Через 60 сек ссылка снова становится доступна как кандидат.

## [1.0.4] - 2026-09-17

### Fixed

- **Observer проверяет резервные ссылки перед добавлением в пул.**
  - Раньше: когда резервная ссылка умирала, observer брал следующую из файла **без проверки** и ставил в пул как `alive: True`.
  - О том, что она тоже мертва, observer узнавал только через 30 секунд — в момент плановой проверки резерва.
  - И так **по одной каждые 30 секунд**, пока не находилась живая. Если 4 резервных оказывались мёртвыми, переключение могло затянуться на **минуты**.
  - Теперь: observer **проверяет кандидата через Xray прямо в момент пополнения пула**.
  - Живая → в резерв. Мёртвая → в deferred, берём следующего кандидата.
  - Продолжает, пока пул не заполнен **или** кандидаты не кончились.
  - Работает **и при старте**, **и во время работы**, **и при переключении**.

- **`switch_to_backup` использует проверку кандидатов.**
  - Когда нет живых резервных — observer **проверяет кандидатов из файла** вместо того, чтобы брать первую попавшуюся.
  - Лучше подождать несколько секунд на проверку, чем переключиться на мёртвую и ждать 25 секунд 5 отказов.

- **`update_pool_from_file` больше не добавляет ссылки в пул без проверки.**
  - Перечитывает `self.links` из файла.
  - Пополнение резерва — только через проверку.

### Changed

- **`refill_pool_excluding_deferred` заменён на `_fill_backup_pool_checked`.**
  - Новая логика: поочерёдная проверка кандидатов.
  - Мёртвые сразу уходят в `deferred_links`.
  - Логи стали подробнее — видно каждого кандидата.

- **Логи стали информативнее.**
  - При пополнении пула:
    ```
    🔍 Пополняем резерв (нужно: 4, в пуле: 0/4)...
    📋 Кандидатов из файла: 25
    🔎 Проверяем кандидата [1]: 194.87.52.83 [US]...
    ✅ 194.87.52.83 [US] живая — в резерв [1/4] (пинг: 120мс)
    ❌ 89.105.206.123 [DE] мертва — в deferred
    ...
    ✅ Резерв пополнен: +4 (проверено кандидатов: 6)
    ```

## [1.0.3] - 2026-09-14

### Added

- **Определение гео ссылок** (`vless_checker.py`).
  - Чекер при проверке рабочей ссылки **запрашивает её страну** через Cloudflare trace (`https://www.cloudflare.com/cdn-cgi/trace`).
  - Результат записывается **в саму ссылку** — в fragment `#COUNTRY`.
  - Формат: `vless://uuid@host:443?params#DE` (страна — код ISO 3166-1 alpha-2).
  - Если гео не определилось — `#UNKNOWN`, ссылка **не отбрасывается**.
  - Если ссылка **уже с `#remark`** — fragment **заменяется** на `#COUNTRY`.
  - Гео определяется **через тот же Xray-процесс**, что и основная проверка.

- **Устойчивый импорт гео-параметров** (`vless_checker.py`).
  - Параметры `GEO_*` читаются через `getattr(cfg, ..., default)`.
  - Если в конфиге нет `GEO_ENABLED` — берётся дефолт `True`.
  - Никаких `NameError` — код работает с любым конфигом.

- **Показ гео в логах observer'а** (`observer.py`).
  - Observer парсит `#COUNTRY` из ссылок и показывает её в логах.
  - Формат: `OK | 188.130.208.210 [DE] | резерв: 4/4 живых | ...`
  - Если `#` нет или fragment не распознан — `[N/A]`.
  - Если `#UNKNOWN` — `[UNKNOWN]`.

- **Гео-распределение в логе чекера** (`save_working_links`).
  - После сохранения ТОП-30 чекер пишет:
    ```
    Гео распределение: DE: 12, NL: 8, US: 5, UNKNOWN: 5
    ```

- **Новые параметры в `vless_check_config.py`:**
  ```python
  GEO_ENABLED = True
  GEO_URL = "https://www.cloudflare.com/cdn-cgi/trace"
  GEO_TIMEOUT = 5
  GEO_UNKNOWN_MARK = "UNKNOWN"
  ```

### Changed

- **`vless_checker.py`: fragment отсекается перед парсингом.**
  - При проверке ссылки через Xray — fragment (`#DE`) **не передаётся** Xray.
  - При сравнении с карантином — сравнение идёт **по базовой части** (без `#`).

- **`observer.py`: сравнение ссылок — без гео.**
  - Карантин, `backup_pool`, `deferred_links` — сравнение идёт по **базовой части** ссылки.
  - Ссылка с `#DE` и без — считаются **одной и той же**.

## [1.0.2] - 2026-09-14

### Added

- **Умное слияние конфигов при обновлении** (`merge_config.py`).
  - Дополняет пользовательские конфиги новыми параметрами из GitHub.
  - Существующие параметры **не трогаются**.
  - Показывает, **что** будет добавлено, и спрашивает подтверждение.
  - При отказе — конфиг остаётся **без изменений**.
  - В режиме `--auto` — слияние **пропускается**.
  - Обрабатывает простые `KEY = VALUE` и многострочные списки/словари.

- **`update.sh` обновляет конфиги через `merge_config.py`.**
  - Конфиги больше **не перезаписываются**.
  - Если `merge_config.py` недоступен — конфиги **вообще не обновляются**.

- **`install.sh` скачивает `merge_config.py`.**

### Changed

- **`update.sh` разделяет обновление кода и конфигов.**
  - **Код** — перезаписывается.
  - **Конфиги** — обрабатываются через `merge_config.py`.

## [1.0.1] - 2026-09-14

### Fixed

- **Observer проверяет ссылки при старте.**
  - Раньше: сразу ставил первую ссылку из `working_links.txt` в outbound 3x-ui, **не проверяя** её.
  - Если она оказывалась мёртвой — начиналось «дёргание»: 5 отказов → переключение → новая мёртвая → 5 отказов.
  - Теперь: observer **перебирает ссылки по одной** и ставит в outbound **только живую**.
  - Резерв наполняется **только живыми** ссылками.
  - Если **все** ссылки в файле мёртвы — observer **не запускает потоки**, ждёт обновления файла от чекера.

- **`init_pool` возвращает `bool`** — `True` нашли живую, `False` — ждём.

- **`run()` — цикл с ожиданием.**

### Changed

- **Старт observer занимает больше времени.**
  - Хороший случай: 5–10 секунд.
  - Плохой случай: 40–90 секунд.
  - Очень плохой: observer ждёт обновления файла.
