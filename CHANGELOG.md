## [1.0.3] - 2026-09-14

### Added

- **Определение гео ссылок** (`vless_checker.py`).
  - Чекер при проверке рабочей ссылки **запрашивает её страну** через Cloudflare trace (`https://www.cloudflare.com/cdn-cgi/trace`).
  - Результат записывается **в саму ссылку** — в fragment `#COUNTRY`.
  - Формат: `vless://uuid@host:443?params#DE` (страна — код ISO 3166-1 alpha-2).
  - Если гео не определилось — `#UNKNOWN`, ссылка **не отбрасывается**.
  - Если ссылка **уже с `#remark`** — fragment **заменяется** на `#COUNTRY`.
  - Гео определяется **через тот же Xray-процесс**, что и основная проверка. Без дополнительных запусков.

- **Устойчивый импорт гео-параметров** (`vless_checker.py`).
  - Параметры `GEO_*` читаются через `getattr(cfg, ..., default)`.
  - Если в конфиге нет `GEO_ENABLED` (пользователь отказался добавлять при обновлении) — берётся дефолт `True`.
  - Никаких `NameError` — код работает с любым конфигом.

- **Показ гео в логах observer'а** (`observer.py`).
  - Observer парсит `#COUNTRY` из ссылок и показывает её в логах.
  - Формат: `OK | 188.130.208.210 [DE] | резерв: 4/4 живых | ...`
  - Если `#` нет или fragment не распознан — `[N/A]`.
  - Если `#UNKNOWN` — `[UNKNOWN]`.
  - Гео видно **везде**: в стартовой проверке, в переключении, в резерве, в deferred, в карантине.

- **Гео-распределение в логе чекера** (`save_working_links`).
  - После сохранения ТОП-30 чекер пишет:
    ```
    Гео распределение: DE: 12, NL: 8, US: 5, UNKNOWN: 5
    ```

- **Новые параметры в `vless_check_config.py`:**
  ```python
  GEO_ENABLED = True
  GEO_URL = "https://www.cloudflare.com/cdn-cgi/trace"
  GEO_TIMEOUT = 5
  GEO_UNKNOWN_MARK = "UNKNOWN"
  ```

### Changed

- **`vless_checker.py`: fragment отсекается перед парсингом.**
  - При проверке ссылки через Xray — fragment (`#DE`) **не передаётся** Xray.
  - При сравнении с карантином — сравнение идёт **по базовой части** (без `#`).
  - Xray работает так же, как раньше.

- **`observer.py`: сравнение ссылок — без гео.**
  - Карантин, `backup_pool`, `deferred_links` — сравнение идёт по **базовой части** ссылки.
  - Ссылка с `#DE` и без — считаются **одной и той же** ссылкой.
  - Это нужно для корректной работы карантина.

### Fixed

- Не выявлено.

## [1.0.2] - 2026-09-14

### Added

- **Умное слияние конфигов при обновлении** (`merge_config.py`).
  - Новый скрипт `merge_config.py` — дополняет пользовательские конфиги новыми параметрами из GitHub.
  - Существующие параметры **не трогаются** — ваши правки сохраняются.
  - Показывает, **что** будет добавлено, и спрашивает подтверждение (`y/n`).
  - При отказе — конфиг остаётся **без изменений**.
  - В режиме `--auto` — слияние **пропускается** с предупреждением.
  - Обрабатывает как простые `KEY = VALUE`, так и многострочные списки/словари.

- **`update.sh` обновляет конфиги через `merge_config.py`.**
  - Конфиги больше **не перезаписываются**.
  - Если `merge_config.py` недоступен — конфиги **вообще не обновляются**.

- **`install.sh` скачивает `merge_config.py`.**
  - При установке — сохраняется в `/root/merge_config.py`.

### Changed

- **`update.sh` разделяет обновление кода и конфигов.**
  - **Код** (`.py` без конфигов, `.sh`) — перезаписывается.
  - **Конфиги** — обрабатываются через `merge_config.py`.

## [1.0.1] - 2026-09-14

### Fixed

- **Observer проверяет ссылки при старте.**
  - Раньше: при запуске сразу ставил первую ссылку из `working_links.txt` в outbound 3x-ui, **не проверяя** её.
  - Если она оказывалась мёртвой — начиналось «дёргание»: 5 отказов → переключение → новая мёртвая → 5 отказов → снова переключение.
  - Теперь: observer **перебирает ссылки по одной** и ставит в outbound **только живую**.
  - Резерв наполняется **только живыми** ссылками. Мёртвые сразу уходят в deferred.
  - Если **все** ссылки в файле мёртвы — observer **не запускает потоки**, ждёт обновления файла от чекера.

- **`init_pool` теперь возвращает `bool`.**
  - `True` — нашли живую основную, работаем.
  - `False` — живых нет, надо ждать обновления от чекера.

- **`run()` — цикл с ожиданием.**
  - Observer не запускает рабочие потоки, пока не найдёт живую основную ссылку.

### Changed

- **Старт observer теперь занимает больше времени.**
  - Хороший случай: 1–2 ссылки проверены → 5–10 секунд.
  - Плохой случай: 10+ мёртвых подряд → 40–90 секунд.
  - Очень плохой: все ссылки мёртвы → observer ждёт обновления файла от чекера.
  - **Компромисс в пользу «подождать на старте, но сразу работать через живую ссылку».**

## [1.0.0] - 2026-09-14

Первый публичный релиз. **Alpha 1.0.**

### Added

- **Этап 1: сбор VLESS-ссылок** (`vless_checker.py`).
  - Скачивание списка с GitHub.
  - Фильтрация по `security=reality` и порту `443`.
  - Проверка каждой ссылки через реальный Xray (HTTPS-запрос на `check.torproject.org`).
  - Отбор ТОП-30 по пингу в `working_links.txt`.

- **Observer: трёхпоточный наблюдатель** (`observer.py`).
  - Поток 1 — проверка основной ссылки каждые 5 сек.
  - Поток 2 — проверка резерва каждые 30 сек.
  - Поток 3 — deferred-ссылки (раз в 10 минут) + обновление пула.
  - Разные порты для потоков: 10808 / 10809 / 10810.
  - Автоматическое переключение outbound'а в 3x-ui через SQLite.
  - Механика отложенных ссылок (deferred) с двумя таймерами: перепроверка раз в 10 минут, удаление через 2 часа.
  - Карантин для ссылок, работающих только на Google.

- **Ротация логов.**
  - Каждый лог ротируется в полночь.
  - Хранится 7 архивов.

- **Graceful shutdown.**
  - SIGTERM/SIGINT handler во всех трёх скриптах.
  - Корректное завершение: закрытие сокетов, убийство дочерних Xray-процессов.

- **Триггеры для отладки** (файлы в `/tmp/`):
  - `vless_observer_trigger` — имитация отказа.
  - `vless_quarantine_trigger` — отправить основную в карантин.
  - `vless_deep_check_trigger` — глубокая проверка.

- **`show_logs.sh` — меню логов и управления.**
  - Просмотр логов Observer, Чекера, cron-обёртки.
  - Статистика переключений.
  - Очистка логов.
  - Триггеры.
  - Статус служб и активных процессов.
  - Просмотр ротированных архивов.
  - Проверка обновлений, обновление, откат.

- **`install.sh` — установщик.**
  - Проверка системы и прав.
  - Установка зависимостей.
  - Скачивание файлов.
  - Настройка cron (01:00, 07:00, 13:00, 19:00) с защитой `flock`.
  - Создание и запуск systemd-службы `vless_observer`.

- **Защита от двойного запуска чекера.**
  - `flock` в cron-задании.

- **Автообновление через `update.sh`.**
  - Проверка версии на GitHub.
  - Бэкап перед обновлением (5 последних).
  - Graceful stop/start observer'а.
  - Откат из последнего бэкапа (`--rollback`).
  - Флаги: `--check`, `--auto`, `--rollback`.

### Changed

- **Observer читает `working_links.txt`** (30 ссылок), а не `stable_links.txt` (10).
- **Отложенные ссылки перепроверяются раз в 10 минут.**
- **Валидация Reality-параметров** (`pbk`, `sid`, `sni`).
- **Обновление `working_links.txt` через атомарную запись.**
- **`reload_xray` больше не использует SIGHUP.**
- **`switch_to_backup` — цикл вместо рекурсии.**

### Fixed

- **`start_time` в начале `test_link_through_xray`.**
- **Сокеты Xray корректно закрываются в `finally`.**
- **`self.primary is None` в финальном логе.**
- **Защита от гонок в `backup_pool`, `dead_links`, `deferred_links`.**
- **Реальная остановка `until_30` в `vless_checker.py`.**
- **`STAGE2_MIN_RESPONSE_SIZE` теперь используется.**
- **`systemd` юнит `vless_observer` корректно завершает службу.**

### Removed

- **`full_check.py`** — не использовался, заменён на `run_full_check.sh`.
