Обучающий материал на тему:

**Каскадный КВН без аренды серверов.** Комбайн по сбору рабочих VLESS-ссылок и их автоматическому обновлению в панели 3x-ui.

## 📖 О проекте

Система для организации каскадного КВН на собственном сервере (например, NanoPi Neo) с панелью **3x-ui**.

**Идея:**

- Берём бесплатные VLESS-ссылки из открытых источников (по умолчанию — [ebrasha/free-v2ray-public-list](https://github.com/ebrasha/free-v2ray-public-list)).
- Проверяем их на **реальное соединение** (не пинг, а полноценный HTTPS-запрос через Xray).
- Определяем **страну** каждой рабочей ссылки и записываем её в саму ссылку (`#DE`, `#NL`, `#US`).
- Автоматически подставляем самую стабильную ссылку в outbound панели 3x-ui.
- Держим 4 резервные ссылки наготове.
- При падении основной ссылки — **мгновенно** переключаемся на резервную.
- Можем отдавать **приоритет конкретной стране** — если она задана в конфиге.

**Что даёт:**

- Не нужно арендовать VPS.
- Не нужно покупать подписку на КВН.
- Нужен только роутер с DDNS (например, Keenetic) и мини-сервер (NanoPi Neo, Raspberry Pi, Orange Pi).
- Не смотря на то, что Keenetic умеет в **Xray** не нужно ставить сторонние библиотеки и ломать домашнюю сеть в случае неудачи.
- Устройства в локальной сети выходят в интернет через каскад(по желанию).
- **Видно, через какую страну идёт трафик.**
- **Управление через файлы-триггеры** — можно подключить Telegram-бот или управлять вручную.

## 🔄 Как это работает

### Этап 1: сбор ссылок (`vless_checker.py`)

1. Скачивает список VLESS-ссылок с GitHub.
2. Фильтрует по признакам из конфига:
   - `security=reality`
   - `port=443`
   - уникальные хосты (без дубликатов)
3. Прогоняет каждую ссылку через реальный Xray-тест (HTTPS-запрос на `check.torproject.org`).
4. **Определяет страну ссылки** через Cloudflare trace.
5. **Записывает страну** в саму ссылку — `#DE`, `#NL`, `#US`.
6. Отбирает **30 лучших по пингу**.
7. Сохраняет в `working_links.txt`.

**Запуск:** по cron 4 раза в сутки (**01:00, 07:00, 13:00, 19:00**).

**Защита от двойного запуска:** через `flock`.

### Observer: удержание связи (`observer.py`)

Работает как systemd-служба в фоне. **Три потока:**

| Поток | Что делает | Интервал |
|-------|-----------|----------|
| **Primary** | Проверяет основную ссылку | каждые 5 сек |
| **Backup** | Проверяет 4 резервные ссылки | каждые 30 сек |
| **Maintenance** | Проверяет отложенные + обновляет пул из файла | 10 мин / 60 сек |

**Ключевые механики:**

- **Проверка при старте.** Observer **не ставит ссылку в outbound, не проверив**. Перебирает ссылки из файла по одной, ставит **только живую**.
- **Переключение:** после 5 отказов подряд основная ссылка заменяется на первую живую из резерва.
- **Отложенные (deferred):** мёртвая ссылка уходит в «отложенные» на 10 минут. Потом перепроверяется. Если ожила — возвращается в резерв. Если мертва 2 часа — удаляется.
- **Карантин:** ссылки, которые работают только на Google, но не работают на запрещённые ресурсы, отправляются в `quarantine_links.txt`.
- **Проверка кандидатов в резерв.** Перед тем как поставить ссылку в резерв — observer **проверяет её через Xray**. Мёртвые уходят в deferred, берётся следующий кандидат.
- **Защита от «круговорота».** После переключения старая основная **не возвращается** в резерв 60 секунд.
- **Приоритетная страна.** Если в `observer_config.py` задан `PREFERRED_COUNTRY = 'DE'` — observer в первую очередь берёт ссылки из Германии. Если таких нет — использует остальные.
- **Триггеры для отладки и управления:** через файлы в `/tmp/`.
- **Гео в логах:** observer показывает страну ссылки — `OK | 188.130.208.210 [DE] | резерв: 4/4 живых | ...`

### Гео ссылок

**Формат:** `vless://uuid@host:443?params#COUNTRY`

**Как определяется:** после успешной проверки ссылки, чекер запускает **тот же Xray** и через него делает запрос к `https://www.cloudflare.com/cdn-cgi/trace`. В ответе ищет `loc=XX`.

**Что если гео не определилось:**
- Ссылка **не отбрасывается**.
- Помечается `#UNKNOWN`.
- Участвует в работе как обычно.

**Что если ссылка уже была с `#remark`:**
- Fragment **заменяется** на `#COUNTRY`.
- Например, `vless://...#MyServer` → `vless://...#DE`.

**Что показывает observer:**
- `[DE]`, `[NL]`, `[US]` — определённая страна.
- `[UNKNOWN]` — не определилась.
- `[N/A]` — в ссылке вообще нет fragment (старые ссылки).

### Приоритетная страна

В `observer_config.py` есть параметр:

```python
PREFERRED_COUNTRY = ""
```

- Пустая строка — **приоритета нет**, все страны равны.
- Код страны (`'DE'`, `'NL'`, `'US'`, ...) — observer **в первую очередь** берёт ссылки с этой страной:
  - при поиске основной при старте;
  - при пополнении резерва из файла.
- Если ссылок с этой страной **нет** или они **мертвы** — observer **добирает** из остальных стран.
- Если код невалидный — **игнорируется** с предупреждением в лог.

В логе при старте:

```
⭐ Приоритетная страна: DE
```

или

```
Приоритетная страна: не задана
```

### Триггеры — управление observer'ом

Observer можно **управлять через файлы-триггеры** в `/tmp/`. Это используется Telegram-ботом (или можно вручную).

**Формат команды:**

| Файл | Действие |
|------|----------|
| `touch /tmp/vless_status_trigger` | Прислать статус (primary, резерв, deferred, перекл) |
| `touch /tmp/vless_links_trigger` | Прислать список всех ссылок |
| `touch /tmp/vless_switch_trigger` | Переключиться на следующую живую из резерва |
| `touch /tmp/vless_geo_DE` | Переключиться на страну DE |
| `touch /tmp/vless_pick_46.28.69.53` | Переключиться на конкретный host |
| `touch /tmp/vless_ignore_46.28.69.53` | Отправить ссылку в карантин |
| `touch /tmp/vless_unignore_46.28.69.53` | Убрать ссылку из карантина |
| `touch /tmp/vless_reload_trigger` | Перечитать `working_links.txt` |

**Ответы** пишутся в `/tmp/vless_<action>_response` в формате **JSON**.

Пример ответа на `/tmp/vless_status_trigger`:

```json
{
  "ok": true,
  "action": "status",
  "timestamp": 1730000000,
  "data": {
    "primary": "89.124.85.87 [NL]",
    "primary_fail_count": 0,
    "backup_alive": 4,
    "backup_total": 4,
    "deferred_count": 0,
    "switch_count": 3
  }
}
```

**Защита от устаревших команд:**
- Если триггер старше `TRIGGER_MAX_AGE` (по умолчанию 30 секунд) — **удаляется без выполнения**.
- При старте observer'а **все старые триггеры и ответы удаляются**.

**Старые триггеры для отладки** (совместимость):
```bash
touch /tmp/vless_observer_trigger      # имитация 5 отказов → переключение
touch /tmp/vless_quarantine_trigger    # основную в карантин
touch /tmp/vless_deep_check_trigger    # глубокая проверка (Google + запрещённые)
```

- **Железо:** NanoPi Neo (ARMv7), Raspberry Pi, Orange Pi или любой ARM-сервер с Debian.

## 🚀 Установка

### Шаг 1. Базовая настройка роутера (Keenetic)

1. Подключите NanoPi, зафиксируйте его IP адрес в роутере на постоянный - в примере 192.168.1.15
2. Зайдите в панель Keenetic → **«Доменное имя»**.
3. Займите свободное имя третьего уровня, например `xxxxx.netcraze.link`.
4. Режим работы — **через облако**.
5. Добавьте **«Доступ к веб-приложениям»**:
   - Имя сервиса: `npi`
   - Получится `npi.xxxxx.netcraze.link`
   - Протокол: **HTTP**, порт **80** (позже поменяем на HTTPS), устройство-ваш NanoPi с адресом 192.168.1.15.
6. Пробросьте порт **443** на IP-адрес NanoPi.
7. На роутере добавить статический маршрут через командную строку в веб-интерфейсе(CLI):
   ```bash
   ip host npi.xxxxx.netcraze.link 192.168.1.15
   system configuration save
   ```

### Шаг 2. Базовая настройка NanoPi
Подключаемся к NanoPi по SSH, например через PuTTY(адрес в примере 192.168.1.15, порт 22) вводим команды:
```bash
apt update && apt upgrade -y
```

Добейтесь безошибочного обновления. Иногда зарубежные репозитории тормозят — можно обновить через КВН.

### Шаг 3. Установка и настройка 3x-ui

Установите панель по методичке из [этого гайда](https://noname-28.gitbook.io/3x-ui-gaid/nastroika-servera), начиная с вкладки «Настройка сервера».

1. Первый блок кода по файрволу — пропустить.
2. Везде, где `yourdomain.com` — использовать `npi.xxxxx.netcraze.link` из Шага 1.
3. Пройти настройку до конца.
4. В Keenetic поменять протокол для `npi.xxxxx.netcraze.link` на **HTTPS**, порт **443**(п.5 шага 1).
5. Зайти в 3x-ui через браузер.
6. Настроить XRAY(входящее соединение) по ссылке в начале шага 3.
7. Проверить тоннель, создав клиента и подключившись.
8. **Создать outbound `vless_obs`:** Исходящие → добавить VLESS → имя `vless_obs` → вставить любую ссылку во вкладку JSON → импорт.
9. **Создать маршрут:** Маршрутизация → Тэг входящего (созданный в п. 5) → Тэг исходящего `vless_obs` → Сохранить.

### Шаг 4. Установка VLESS CASCADE

```bash
wget -qO- https://raw.githubusercontent.com/PsoyNe/vless_cascade/refs/heads/main/install.sh | bash
```

Скрипт:

- Установит зависимости.
- Скачает чекер и observer в `/root/vless_checker/` и `/root/vless_observer/`.
- Скачает `update.sh` и `merge_config.py` в `/root/`.
- Сохранит версию в `/root/.vless_cascade_version`.
- Настроит cron на этап 1 (01:00, 07:00, 13:00, 19:00) с защитой `flock`.
- Создаст и запустит systemd-службу `vless_observer`.

## 🔄 Обновление

### Проверить наличие обновлений

```bash
bash /root/update.sh --check
```

### Обновить (с подтверждением)

```bash
bash /root/update.sh
```

**Что произойдёт:**

1. Проверит версию на GitHub.
2. Покажет, что нового (из `CHANGELOG.md`).
3. Спросит подтверждение.
4. Создаст бэкап в `/root/vless_backup_YYYYMMDD_HHMMSS/`.
5. Остановит observer.
6. **Обновит код** — заменой файлов.
7. **Обновит конфиги** — через **умное слияние** (см. ниже).
8. Обновит `/root/.vless_cascade_version`.
9. Запустит observer.

### Умное слияние конфигов

**Проблема:** при обычном обновлении ваши правки в `vless_check_config.py` и `observer_config.py` **теряются**.

**Решение:** `merge_config.py` — **дополняет** ваши конфиги новыми параметрами, **не трогая существующие**.

**Как это выглядит:**

```
============================================================
 КОНФИГИ (умное слияние)
============================================================

[INFO] Чекер: vless_check_config.py

============================================================
[WARNING] vless_check_config.py: найдены новые параметры
============================================================

# --- ГЕО ---
GEO_ENABLED = True
GEO_URL = "https://www.cloudflare.com/cdn-cgi/trace"
GEO_TIMEOUT = 5
GEO_UNKNOWN_MARK = "UNKNOWN"

============================================================

Добавить эти параметры в vless_check_config.py? (y/n): y
[OK] vless_check_config.py: добавлено параметров: 4
[OK] Добавлено: GEO_ENABLED, GEO_URL, GEO_TIMEOUT, GEO_UNKNOWN_MARK
```

- **`y`** — параметры добавятся в конец. Ваши настройки **не тронутся**.
- **`n`** — конфиг останется **без изменений**. Код **всё равно работает** (использует дефолты через `getattr`).

### Обновить без вопросов (для автоматизации)

```bash
bash /root/update.sh --auto
```

Флаг `--auto` — не задаёт вопросов. **Слияние конфигов пропускается**.

> ⚠️ **Не рекомендуется** включать `--auto` в cron.

### Откатиться из последнего бэкапа

```bash
bash /root/update.sh --rollback
```

### Обновление одной командой

```bash
wget -qO- https://raw.githubusercontent.com/PsoyNe/vless_cascade/main/update.sh | bash
```

### Бэкапы

`/root/vless_backup_YYYYMMDD_HHMMSS/`. Хранятся **5 последних**.

```bash
crontab -l | grep vless_checker    # проверить

```

По умолчанию:


```bash
systemctl status vless_observer    # статус
systemctl restart vless_observer   # перезапуск
systemctl stop vless_observer      # остановка (SIGTERM, graceful)
```

- **Проверка обновлений, обновление, откат.**
- **Просмотр и редактирование конфигов чекера и observer'а** (с бэкапом и проверкой синтаксиса).

- **Редактирование конфига + перезапуск observer'а.**

```bash
sleep 6
cat /tmp/vless_status_response | jq

# Список ссылок
touch /tmp/vless_links_trigger
sleep 6
cat /tmp/vless_links_response | jq

# Переключиться на страну DE
touch /tmp/vless_geo_DE
sleep 6
cat /tmp/vless_geo_DE_response | jq

# Переключиться на конкретный host
touch /tmp/vless_pick_46.28.69.53
sleep 6
cat /tmp/vless_pick_46.28.69.53_response | jq

# Отправить в карантин
touch /tmp/vless_ignore_46.28.69.53

# Убрать из карантина
touch /tmp/vless_unignore_46.28.69.53

# Перечитать файл ссылок
touch /tmp/vless_reload_trigger
```

**Ответы** — JSON в `/tmp/vless_<action>_response`.

> 💡 Триггеры живут **30 секунд**. Если observer не успел обработать — файл удаляется без выполнения. Это защита от устаревших команд.

## 🔥 Особенности
Важно понимать, что проект задумывался как максимально удешевлённый механизм каскада. На момент написания статьи Nano pi neo v1.31 по цене 800р на [Авито](https://www.avito.ru/moskva_zelenograd/nastolnye_kompyutery/mini_pk_odnoplatnyy_8189267925?slocation=621540&context=H4sIAAAAAAAA_wE_AMD_YToyOntzOjEzOiJsb2NhbFByaW9yaXR5IjtiOjA7czoxOiJ4IjtzOjE2OiJSQmNMbjlxVjhNVk5WRG5zIjt96Rt0OD8AAAA), ищите. Всё это можно применить и на арендном VPS сервере с поправкой на архитектуру железа и правкой под него кода.

1. **Ссылки берутся из открытых источников.**
2. **NanoPi Neo (256/512 МБ)** — оптимальная платформа.
3. **Тестируется реальный доступ через Xray**, а не просто пинг.
4. **Фильтр на входе:** только `security=reality` + порт `443` или один из этого или без фильтра(все подряд).
5. **Балансировщик 3x-ui не используется.** Своя обсерватория.
6. **Observer держит 1 основную + 4 резервных.**
7. **Три потока в observer.**
8. **Умное слияние конфигов.** Ваши правки **не теряются**.
9. **Гео ссылок.** В `working_links.txt` каждая ссылка помечена страной.
10. **Приоритетная страна.** Можно задать страну, которая всегда в приоритете.
11. **Управление через триггеры.** Файлы в `/tmp/` — команды для observer'а.
12. **Защита от устаревших команд.** Триггеры старше 30 секунд игнорируются.

## 🎁 Бонус: прокси на 1080 порту

В панели 3x-ui можно поднять **входящее соединение `mixed` на порту 1080**. Отключить авторизацию при создании этого входящего, добавить маршрут: выбрать только тэг этого входящего и тэг исходящего(vless_obs).

В Keenetic:

1. Настроить подключение к этому прокси(другие подключения-добавить-socks5-назвать-адрес:192.168.1.15:1080-галку использовать для выхода в интернет-сохранить-включить).
2. Создать политику доступа через этот прокси(приоритеты подключений-добавить политику-назвать-вытянуть на верх созданное в п.1 подключение и поставить на нём галку-сохранить).
3. Назначить устройствам в сети выход через политику с названием из п.2.
